## Назначение

Обновление должно освобождать завершённые соединения и их служебное состояние вовремя, сохраняя возможности fork. Синхронизация переносит полную проверенную upstream-линию, а не отдельные изменения, достаточные только для компиляции.

Текущая ветка уже использует 1.15 alpha. Переход на stable 1.14 означал бы смену поколения и потерю части контракта. Поэтому сохраняется существующий testing-канал; точный commit записывается отдельно от версии.

## Требования

1. Сохранить историю обычным merge без force-push и сохранить module path `github.com/sagernet/sing-box`.
2. Сохранить AWG, XHTTP, VLESS Encryption, eBPF, DNS-группы, URLTest, idle-suspend и полный набор производственных build-тегов. Уже исправленные fork выделения socket-diag и sniff не теряются.
3. Обновить sing-tun целиком до версии, требуемой целевым upstream. Проверить завершение TCP-handshake, FIN/RST и очистку flow/session state по фактическому коду зависимости.
4. Перенести handshake-failure cleanup и синхронизацию AttachFlow/CloseFlow из upstream. Регрессии должны проверять освобождение ресурсов и отсутствие гонки при перекрывающихся вызовах AttachFlow/CloseFlow, включая завершение регистрации в группе до публикации callback её удаления.
5. Обновить tracked-копию `submodules/wireguard-go` полной разницей исходных деревьев до `fdf0ad046586`, сохранив AWG и bind recovery. Новые require-версии не должны скрывать старый код под local replace.
6. Сохранять размер UDP/GRO-буфера, production-теги и текущие значения GOMEMLIMIT/GOGC. Экономия памяти должна следовать из жизненного цикла и измеренных выделений, а не из урезания функций или учащения GC.
7. Сначала обновляются требования; затем реализация; затем проверенные commit-пины в magicnet-android и MagicNet. Более новые изменения UI потребителя сохраняются.

## Приёмка

- Обычная сборка и целевые tests/vet проходят; критичные lifecycle-пути проходят race detector.
- Полный производственный CLI собирается для Linux amd64 и Android arm64 с `-mod=readonly`, `GOTOOLCHAIN=local`, `GOWORK=off`.
- Регрессии подтверждают cleanup при ошибке handshake, безопасный CloseFlow/AttachFlow и сохранение WireGuard/AWG поведения.
- Сравнение с исходным commit использует одинаковые Go, теги и нагрузку. Отдельно указываются heap allocations, retained state и RSS; одно не подменяет другое.
- Отчёт перечисляет реальные результаты и ограничения. Снижение RSS на Android и работа реального туннеля требуют отдельного device-прогона; без него процент экономии и device-verified статус не заявляются.
- Перед публикацией релизного тега обязателен device-прогон после WireGuard изменений. Эта задача обновляет проверяемый исходный код и фиксированные ссылки; релизный тег не создаётся автоматически.
