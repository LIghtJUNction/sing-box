## Контракт

В Android CLI отсутствие результата у монитора default-интерфейса не
доказывает отсутствие системного маршрута. Если `auto_detect_interface=false`,
нет platform adapter и явно заданных default interface/network strategy,
ядро оставляет сетевые рабочие процессы активными и передаёт выбор маршрута
Android. Ошибки реальных сокетов сохраняются; доступность сети не объявляется.

В остальных режимах потеря default-интерфейса приостанавливает сетевые
рабочие процессы и сообщает об ожидании интерфейса. На любой потере отменяется
предыдущая асинхронная обработка интерфейса. Новый достоверный интерфейс
возобновляет обычную обработку и сброс соединений; отсутствие интерфейса
не подменяется вымышленным именем или индексом.

## Основание и границы

`route/network.go` создаёт монитор и вызывает `NetworkPause()` при `nil`
даже при выключенном auto-detect. Фиксированный `sing-tun` выбирает Android
таблицу по маске `0xffff`; OEM policy rules или ещё не подключённая сеть
могут не дать результата. Лог пользователя доказывает отсутствие результата
монитора, но не различает эти два случая.

DHCP без явно указанного интерфейса, правила по default interface и
потребители с обязательной привязкой продолжают видеть `nil` и сообщать
свои ошибки. Фикс не создаёт маршруты, не назначает `wlan0` и не меняет
`sing-tun`. Проверка Android Wi-Fi/сотовой сети остаётся отдельной.

## Приёмка

- Только Android CLI с необязательным монитором сохраняет системные попытки.
- Auto-detect, platform adapter и явные default interface/network strategy
  сохраняют паузу при отсутствии интерфейса.
- Потеря отменяет старый контекст; повторная потеря сохраняет pending reset.
- Восстановление через существующий callback выполняет wake/reset.
- Device pause не снимается сетевым восстановлением.
- Снятие патча: upstream разделит необязательное наблюдение интерфейса
  и обязательное условие для сетевой паузы.
